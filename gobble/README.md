# gobble CLI

Command-line tool that simulates a Solana transaction and detects whether any inner program reads forbidden bytes from the instructions sysvar. Used to identify programs that snoop on slippage parameters (e.g. `min_amount_out` at bytes 8-16) during CPI.

## Usage

```
gobble <TRANSACTION> [OPTIONS]
```

### Arguments

- `<TRANSACTION>` — Base58-encoded `VersionedTransaction` (legacy or V0 with address lookup tables)

### Options

- `-r, --rpc-url <URL>` — Solana RPC endpoint (default: `https://api.mainnet-beta.solana.com`)
- `-i, --instruction-index <N>` — Which instruction to watch, 0-based (default: `0`)
- `-f, --forbidden-ranges <RANGES>` — Comma-separated byte ranges to flag as forbidden (default: `8-16`). Example: `8-16,20-24`

### Exit codes

- `0` — No forbidden access detected
- `1` — Forbidden access detected

### Example

```bash
cargo build -p gobble

./target/debug/gobble \
  '<bs58-encoded-transaction>' \
  -f 8-16 \
  --rpc-url https://api.mainnet-beta.solana.com
```

## How it works

1. Decodes the bs58 transaction and resolves all account keys (including V0 address lookup tables)
2. Fetches accounts and program data from RPC
3. Constructs the instructions sysvar from the transaction's message
4. Calculates which byte offsets in the sysvar correspond to the forbidden instruction data ranges
5. Loads programs into a modified Agave runtime with a modified SBPF VM that tracks memory reads
6. Executes the transaction and reports whether any program read the forbidden byte ranges

## example.sh

`example.sh` runs three pre-built test transactions against mainnet-deployed programs:

| Test | Route | Expected |
|------|-------|----------|
| 1 | Router -> Gobble | **TRUE POSITIVE** — gobble reads bytes 8-16 via sysvar |
| 2 | Router -> AMM | **TRUE NEGATIVE** — amm only reads its CPI data |
| 3 | Router -> GobbleSolana | **FALSE POSITIVE** — `load_instruction_at_checked` deserializes all bytes |

Run it:
```bash
cd gobble
bash example.sh
# or with a custom RPC:
RPC_URL=https://your-rpc.example.com bash example.sh
```

### How the test transactions were generated

The bs58-encoded transactions in `example.sh` were generated by the `txn` example in `gobble-lib`:

```bash
cargo run --example txn -p gobble-lib
```

This builds unsigned `VersionedTransaction`s that invoke the router program with each target program (gobble, amm, gobble-solana) as an account. The router's instruction data is 16 bytes: an 8-byte discriminator followed by an 8-byte `min_amount_out`. The CLI doesn't need valid signatures — it only needs the message structure to fetch accounts and simulate execution.
